**The `_ord` encrypted-domain variants are now backed by CLLW-OPE (`op`) instead of block-ORE (`ob`).** `public.<T>_ord` (every ordered scalar) and `public.text_ord` now carry the `op` term and are ordered by native `bytea` comparison. The ordering extractor keeps its name — `eql_v3.ord_term(col)` — but now returns `eql_v3_internal.ope_cllw`. Because `ope_cllw` is a domain over `bytea`, a functional btree on `eql_v3.ord_term(col)` uses the default operator class — no custom comparator, no `pgcrypto` in the compare path, and no superuser-only operator class, so ordered indexes now work on Supabase and other managed PostgreSQL without privilege escalation. The extractor name tracks the domain rather than the cipher: block-ORE is still fully supported behind `public.<T>_ord_ore`, whose extractor is now the qualified `eql_v3.ord_term_ore(col)`; `public.text_search` remains `[hm, ob, bf]`; and `_ord` / `_ord_ope` are now the byte-identical twins. Three consequences for callers: rows stored in an `_ord` column must carry `op` rather than `ob` (so existing `_ord` indexes must be rebuilt), `eql_v3.ord_term(public.<T>_ord_ore)` is renamed to `eql_v3.ord_term_ore` (a pure rename — same term, same behaviour, DDL text only), and the pre-release-only `eql_v3.ord_ope_term` is removed, its overloads folded into `eql_v3.ord_term`. Two behaviour changes follow from the SEM swap. `public.text_ord` now **accepts** the empty string — it sorts first, because OPE encrypts `""` to a well-formed one-byte term, whereas block-ORE produces an unorderable empty array (`ob: []`) that `text_ord_ore` still rejects. And on `real` / `double`, `public.<T>_ord` now distinguishes `-0.0` from `+0.0` (`-0.0 < +0.0`, and `-0.0 <> +0.0`), because block-ORE canonicalizes the sign of zero via `orderable-bytes` and CLLW-OPE does not; this makes `_ord` consistent with `public.<T>_eq`, which already distinguished them. See [U-003](https://github.com/cipherstash/encrypt-query-language/blob/main/docs/upgrading/v3.0.md#u-003-_ord-domains-are-backed-by-cllw-ope).
